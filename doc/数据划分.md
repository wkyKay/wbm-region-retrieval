# 数据划分与评价

当前使用与 compared_methods 一致的冻结去重协议，不再使用旧的 2,000 query × 1,000 候选协议。

## 数据怎么分

原始 Mixed-WM38 有 38,015 条记录。完整原图按 0/1/2/3 像素精确去重，过滤 1,024 条冗余记录；保留 35,991 张缺陷图和 1,000 张 Normal。缺陷图按 37 种完整标签组合分层，seed=2026。

| 集合 | 图像数 | query 数 | 每个 query 的候选数 |
|---|---:|---:|---:|
| train | 25,193 | 不作正式检索评价 | — |
| valid | 3,599 | 固定 500 | 3,598 |
| test | 7,199 | 全部 7,199 | 7,198 |

每个 query 检索本集合完整图库并排除自身；Normal 不进入缺陷检索库。`sample_id` 始终是原始 NPZ 行号，不能换成 CSV 行号。标签顺序为 center、donut、edge-loc、edge-ring、loc、near-full、scratch、random。

冻结文件位于 [deduplicated](../protocol/deduplicated/) 和 [retrieval_v1](../protocol/retrieval_v1/)，加载时检查哈希，不重新抽样。文件职责见 [协议说明](../protocol/README.md)。

## 两套评价有什么区别

| 名称 | 判断什么 |
|---|---|
| exact | 查询和候选的完整标签组合完全相同才命中 |
| coverage | 候选覆盖了查询多少种标签，允许候选有额外标签 |
| FullCoverage | 查询的全部标签都被候选覆盖 |

它们评价同一份检索排名，不是只挑含两个标签的样本。K=1、5、10、20、50、100、500；报告总体、类别宏平均、单/混合及标签数量分组。Recall/AP 的正样本分母及 coverage 的理想排名均取完整候选库；只保存 Top-500，不能称为完整排名或 full mAP。

跨组合协议还会提前排除完整标签组合相同的候选，只评价 coverage，必须单独列结果。目前七方法跨组合中的 F 是旧版本。公式与零分母处理统一见对比项目的 [数据划分与评价](https://github.com/wkyKay/wbm-matching/blob/main/docs/%E6%95%B0%E6%8D%AE%E5%88%92%E5%88%86.md)。
