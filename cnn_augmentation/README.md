# 区域CNN的五种单独增强比较

将Kahng与Kim（2021）的五种输入增强迁移到当前八连通区域CNN，分别与已有直角旋转基线比较。公共协议与登记规则见[项目说明](../doc/项目说明.md)和[结果登记](../results_catalog/README.md)。本实验在本目录独立实现，旧模型、`cnn_refinement/`及历史结果保持只读。

## 原文与实现依据

论文§III-A、表II和图3比较裁剪、Cutout、噪声、旋转与平移。裁剪在多数设置较强，旋转在少标签设置有优势；ResNet18的六档标注比例中裁剪最佳四档、旋转最佳两档。表II是使用标注数据微调后的分类macro-F1，作者分类训练也应用所选增强，不能直接推断无标签区域检索收益。本实验不重复其分类／微调流程，不与其macro-F1作数值排名。

参数依据[作者代码](https://github.com/hgkahng/WaPIRL/blob/10e24c3bbec1ebe98ed32bef8faa86206042ef58/datasets/transforms.py)以及其使用的Albumentations 0.4.6（commit `70452cd040f782dcaca1b19964d6eafe7e5d14eb`）。PDF字节哈希、表II数值和作者版本记录于[机器来源记录](paper_source.json)。复现的是操作与分布，不声称复现作者随机数序列或分类成绩。

| 单独增强 | 固定设置 | 当前三通道输入的处理 |
|---|---|---|
| 裁剪 | 随机面积比例0.5–1.0，宽高比0.9–1.1，nearest恢复96×96 | 缺陷、目标、有效晶圆三通道使用相同裁剪；保留作者库十次尝试和中心fallback规则 |
| Cutout | 以0.5概率应用4个边长19的孔，边界截断，填0 | 三通道同孔删除，包括孔内目标和晶圆支持；实际孔可能重叠 |
| 噪声 | 有效晶圆内每像素以0.05概率被选中，再等概率设为正常／缺陷 | 更新缺陷通道；目标变为原目标与新缺陷的交集，有效晶圆不变；实际变值概率约0.025，不是5%全部翻转 |
| 任意角旋转 | 均匀−180°至180°，nearest，边界填0 | 三通道同步，保留作者OpenCV中心(48,48)；与原np.rot90直角旋转不同 |
| 平移 | 每轴均匀±25%边长，nearest，边界填0 | 三通道同步，不额外旋转或缩放 |

五种变换均作用在F已有的96×96缓存输入上，原52→96固定预处理保持不变。作者crop和shift可先在原尺寸操作再resize；本轮统一在96缓存操作是面向F的明确适配，不宣称逐像素等同整晶圆原流程。几何变换不重新分割；不额外按目标保留率拒绝、重抽或恢复目标，因此部分视图可能失去目标。用同变换的源像素ID记录真实保留率，避免把裁剪放大后的输出像素数当成保留率。

## 控制设置与评价

只训练五个新模型，已有seed2026、`best_nce`第100轮基线直接复用。五组使用原seed2026初始化，保持三通道ResNet18、GAP h512／z128、SGD、NCE、memory bank、每次5000个有放回负例，以及100轮／39,000步；不与上一轮上下文删除或负例过滤叠加。训练仅替换第二视图，第一视图和检索都用完整原窗口；各增强使用独立按token／epoch确定的随机流。固定取第100轮，原旋转valid NCE只作共同诊断，不用于重新选checkpoint。

使用去重后的25,193／3,599／7,199划分，valid固定500query与完整3,599gallery，test全部7,199query与完整gallery；排除自身。每模型均报告CNN单独评分与论文固定融合`0.75*(0.4*C+0.6*T)+0.25*A`，区域、结构／面积项、单向贪心一对一和`sqrt(area)`聚合保持不变。这里检验F区域编码器的增强改动，两个固定评分端点分别揭示深度分支与当前论文融合的表现。

普通exact／coverage同排名，跨组合先排除同完整标签组合再从完整得分重排，分表呈现。保留K=1/5/10/20/50/100/500、总体、组合宏平均、单／混合、标签数及逐类／逐query。主报告含exact P@10和mAP@100、coverage nDCG@10及FullCoverage P@10／mAP@100；2000次组合内配对bootstrap只给出固定模型／图库条件区间，不代表跨seed稳定性或多重比较校正。

五组均完整评价，不按valid或test好坏筛除。沿用预设检索目标：融合P@10提高至少1个百分点且差值95%区间下界大于0，跨组合nDCG@10差值区间下界高于−0.5个百分点；若声称编码器改善，还须CNN单独检索有支持。保留所有正负差及指标取舍，不因某项test最佳自动替换主方法。

## 独立入口与产物

在原PyTorch 2.4 CUDA环境及OpenCV环境、仓库根目录执行。严格初始化哈希检查会拒绝生成不同初始权重的其他PyTorch版本；不能为适应本地版本放宽来源校验。`init`输出真实时间型目录，后续`RUN`使用该路径。

```bash
python -u -m cnn_augmentation.run --stage init
python -u -m cnn_augmentation.run --stage audit --output-root "$RUN"
python -u -m cnn_augmentation.followthrough --output-root "$RUN" --gpus 1 2 3
python -m cnn_augmentation.register --run-root "$RUN" --apply
```

续行器只启动预设五模型，空闲GPU先承接尚未开始的训练，再承接已完成模型的valid/test评价，最后生成报告并封存。每次启动持久化进程与命令，日志保存在`logs/`；阶段失败立即停止调度并保留产物。`--resume`仅复用已验收阶段或接管仍存活进程，不自动重试失败阶段。确需从完整`last.pt`恢复训练时，显式使用`run --stage train --variant <名称> --output-root "$RUN" --resume`，保留原运行身份。

训练前审计同一1024个train区域，保存逐token实际变换、目标／支持保留率及确定性8例输入图。每轮另累计全部99,786个token的实际干预计数，最终报告100轮曝光。报告包括训练曲线、增强曝光、valid/test配对检索图及完整指标表。8个既有基线评价角色沿用原key；只有五新模型×两评分×四协议角色，共40项待完成后登记。官方collect/check与两套归档验证按公共规则执行，不用部分日志冒充完成结果。
